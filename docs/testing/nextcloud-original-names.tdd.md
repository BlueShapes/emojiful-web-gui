# Nextcloudの元の名前を保持して修正を促す

2026-10-17。日本語を含むファイル名が `nya_png_6` などに自動変換され、名前を修正する手がかりが消えていた問題を修正した。

## 原因と変更

取り込みで `nameFromUrl` によるASCII化・小文字化・空白置換・64文字への切り詰めを行い、その結果の衝突を拡張子や連番で区別していた。このため `ショパン-nya.png` と `バッハ-nya.png` の異なる日本語部分が消えていた。

- Nextcloudの名前欄は、最後の拡張子だけを除いた原文を初期値にする。日本語・空白・記号・ASCIIの大文字・64文字超の名前も保持する。自動スラッグ化、代替名の生成、重複回避サフィックスを廃止した。
- `sourceFilename` に完全な元のファイル名を保持し、表の名前欄の下に22言語対応のラベルとともに表示する。個別編集・一括置換・入力方法の切り替えで参照を失わない。長い文字列も折り返し、スクリーンリーダーから名前欄の説明として参照できる。
- 取り込み前の表では不正な名前を保持し、既存の厳密な登録バリデーターでエラーを表示する。使用できない文字・64文字超・重複・標準名との衝突が残る間は一括追加を拒否する。
- 同じstemのGIF・PNGも、別々のURLと元のファイル名のまま保持して重複の修正を促す。名前の編集で画像URLは変えない。
- 元のファイル名は確認用のメタデータとし、登録した絵文字や下書きのスキーマへ混入させない。JSONの1.5 MiB制限の計算からも確認用メタデータを除く。
- XMLのスコープ・パス・URL・カテゴリー・ファイルサイズ・画像件数の安全性検証は維持する。単なる `png` や `GIF` のようにドットがない名前を拡張子付き画像として扱わない。

## RED → GREEN

REDチェックポイントは `2185f31`。既存の5引数APIを維持した回帰テスト7件中3件が、原文の変換・切り詰め、元のファイル名の欠落、重複時の自動サフィックス追加を理由に失敗し、4件が成功した。

実装後は同じ7件が成功した。独立レビューで、ドットのない `png` が `pn` に切り詰められる境界ケースを発見したため、該当ケースの追加テストが失敗することを確認し、拡張子の区切りがないファイルを除外して7件すべて成功する状態に戻した。
