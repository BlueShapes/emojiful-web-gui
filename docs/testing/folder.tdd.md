# パックフォルダーの読み込み・直接保存の検証

2026-10-15。ユーザーの「ZIP以外にフォルダーを選択し、選択したフォルダーを直接操作したい」という依頼に対する実装と検証。

## 仕様と範囲

- 対応ブラウザーでは、ユーザー操作で選んだディレクトリを読み込み、明示的な「フォルダーに保存」で元の絵文字レシピと管理用メタデータを更新する。
- フォルダーの参照は下書き固有のキーに関連付け、IndexedDBに保存する。再読み込み・言語切り替え・他パックの編集で保存先を取り違えない。
- 非対応ブラウザーはフォルダーのファイル選択による読み取り専用インポートを使う。ZIP出力は引き続き利用できる。
- 選択したパックの管理対象ファイルだけを更新し、他のレシピ、画像、メモやディレクトリを削除しない。外部変更・保存先の衝突を検出したら保存を止める。
- 複数ファイルの保存はOS上の単一トランザクションではない。途中の失敗時は元の内容への復元を試み、復元できなかった場合も成功と案内しない。

## レビューで確認・修正した点

- `constructor` や `__proto__` も有効な絵文字名として扱えるよう、名前をキーにした辞書の継承プロパティ参照を防いだ。
- 読み取り専用の取り込みでは、無関係なバイナリ画像や大きなアセットをJSONとして読み込まない。
- 改名で古い保存先を再利用しても、自分の出力を削除対象にしない。
- 絵文字だけの編集で、装飾付きのMinecraftパック説明を失わない。
- GUIメタデータはレシピの更新・削除後に保存し、復元対象を各操作より前に記録する。
- 読み込んだモデルと保存状態のモデルを共有参照にせず、未保存判定の基準を維持する。
- IndexedDBのリクエスト失敗とトランザクション中断の両方を処理する。記録失敗時も現在の画面ではフォルダー参照を保持する。

追加したIndexedDB中断テストは、一度、複合表示に対する完全一致セレクターで失敗した。失敗時の画面には案内が表示されていることを確認し、文言の包含を検証する形に修正して成功した。製品コードの問題としては扱っていない。

## 検証方法の限界

ブラウザーテストは、選択ダイアログだけを置き換え、ネイティブのOPFSディレクトリ／ファイルハンドル、実際の読み書きAPIとIndexedDBで検証した。ユーザーのOS上のフォルダーは操作していない。OSのフォルダー選択ダイアログ自体と実際のブラウザー権限ダイアログは自動化対象にしていない。
Minecraftの起動、変更のないJava APIテスト、Workers配信テスト、ZIP形式処理の全単体テストは再実行していない。カバレッジ収集用のプロバイダーは追加しておらず、網羅率の数値は収集していない。

APIの参照先: [Chrome File System Access API](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access/)、[MDN webkitdirectory](https://developer.mozilla.org/en-US/docs/Web/API/HTMLInputElement/webkitdirectory)。
